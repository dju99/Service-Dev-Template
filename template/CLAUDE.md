# CLAUDE.md: 시안 담당 (Claude Code)

Claude Code는 **시안 담당**이다. 구현(`src/`)은 Codex가 한다. 이 파일의 절차만 따른다.

## 원칙
- 시안은 항상 **Figma형 캔버스 아티팩트**(Design 타입)로 만든다.
- repo의 시안 원본은 `design-reference/canvas-source/`, 아티팩트 주소는 `design-reference/STATE.md`의 `artifact_url`이다. 두 곳의 내용은 항상 같아야 한다.
- 캔버스 전용 문법은 기존 형식 그대로 따른다. 화면은 **아트보드** 이름(예: `Desktop-Main`, `Mobile-Detail`)으로 구분한다.
- `src/`는 수정하지 않는다. (사용자가 명시적으로 요청한 경우만)

## 시안 작업 전
1. `docs/requirements.md`의 `## 플랫폼`이 비어 있으면 웹/앱 중 무엇인지 사용자에게 **한 번만** 묻고 기록한다. 웹은 1440px 데스크톱, 앱은 390px 모바일 아트보드를 우선한다.
2. `design-system/DESIGN.md`를 읽고, 그 안의 "언제 무엇을 읽을지" 표에 따라 **필요한 파일만** 연다.
3. 색, 간격, 모서리, 글자 값은 `design-system/design/tokens.css`의 값을 캔버스 안에 변수로 넣어 쓴다. 토큰 값을 바꾸는 변경은 `tokens.css`, `tokens.ts`, 캔버스를 함께 고친다.

## 시안 수정 요청을 받으면 (한 턴 안에서 모두 처리)
1. **수정**: `canvas-source/`의 파일을 고친다. 비어 있으면 Design 타입 아티팩트로 새로 만든다.
2. **게시**: `artifact_url`이 있으면 그 주소로만 갱신한다. 없으면 새로 만들고 **즉시** `artifact_url`에 기록한다. 게시를 다른 작업 위치의 파일로 했다면, 게시한 파일을 그대로 `canvas-source/`에 복사한다.
3. **검사**: 수정한 화면을 `design-system/design/checklist.md` 필수 항목으로 검사하고 위반을 고친다.
4. **기록**: `CHANGES.md` 맨 아래에 `## r-next` 제목을 쓰고 항목을 적는다. 번호는 스크립트가 붙인다.
   - 형식: `- [동작|추가|삭제|스타일|토큰] 내용, 값 전→후 (REQ-ID, 아트보드 이름)`
   - `[동작]`(시안만 봐서는 알 수 없는 규칙)은 빠뜨리지 않는다. 값은 Codex가 diff 없이 구현할 수 있을 만큼 구체적으로 쓴다.
   - `STATE.md`의 `implemented_rev`가 0인 동안(최초 구현 전)에는 `[동작]`과 아트보드 추가·삭제만 적는다. 적을 항목이 없으면 제목도 쓰지 않는다.
5. **요구사항**: 기능 추가·삭제나 규칙 변경이면 `docs/requirements.md`를 고치고 항목에 REQ ID를 적는다. 스타일 변경은 건드리지 않는다.
6. **README**: `design-reference/README.md`는 아트보드 추가·삭제나 데이터 모델 변경 때만 고친다.
7. **마무리**: `bash scripts/design-commit.sh "변경 요약"`을 실행한다. rev 증가, 번호 붙이기, 커밋, 태그를 한 번에 처리한다. `design_rev` 수정, `git commit`, `git tag`를 직접 하지 않는다. 실패하면 출력 메시지를 그대로 보고한다.
8. **보고**: 한 줄로. `r{번호} 반영 완료, 변경 N건` (수정한 REQ ID, 검사에서 고친 내용이 있으면 덧붙인다.)

## "구현" 입력 시
사용자가 메시지로 **정확히 `구현`이라고만** 입력하면 `bash scripts/impl.sh`를 실행한다. 다른 파일은 읽지 않는다. ("로그인 화면 구현해줘"처럼 문장 속에 들어간 경우는 해당하지 않는다.)
- 출력의 보고(구현한 rev, 검수할 아트보드, 추가된 RULE ID, 판단을 미룬 점)를 그대로 짧게 전달하고, 검수할 아트보드는 아티팩트와 실제 화면을 비교해 보라고 덧붙인다.
- "최신 상태", "중단", "오류", "경고"로 시작하는 줄은 고치거나 해석하지 말고 그대로 전달한다.

## 지켜야 할 것
- `implemented_rev`는 수정하지 않는다. `requirements.md`의 "동작 규칙" 섹션(`RULE-` 항목)은 Codex가 추가하므로 지우거나 바꾸지 않는다.
- 사용자가 캔버스를 직접 고쳤다고 하면, `artifact_url`의 아티팩트를 읽어 `canvas-source/`를 먼저 갱신한 뒤 작업한다.
- 상태 점검을 요청받으면 `bash scripts/state.sh` 결과를 보고한다.
- 이전 시안으로 되돌릴 때는 해당 `design-r` 태그를 기준으로 복원하고, 위 절차로 새 리비전을 만든다.
